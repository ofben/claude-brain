What Does This Thing Actually Do?

Meet Claude Brain — an interactive course delivered entirely by an AI tutor

The Problem It Solves

Imagine you're a writer juggling three clients, a personal newsletter, and a growing pile of research notes. Your ideas are scattered across different apps, different folders, different days. You know you wrote something brilliant about digital minimalism last week — but where?

That's the world of Alex Rivera, the fictional freelance writer at the heart of Claude Brain. Alex's notes are a mess. And the course teaches real people how to fix that — by combining two tools into one powerful system.

Two Tools, One System

📝
Obsidian

A note-taking app where every note can link to every other note — like a personal Wikipedia. It stores your notes as plain text files on your own computer.

🤖
Claude Code

An AI assistant that runs in your terminal and can read, search, and write files on your computer — including your Obsidian notes.

🧠
Claude Brain = Both Together

Claude reads your scattered notes, finds hidden connections between them, and helps you build a structured "second brain" — an organized, searchable web of knowledge.

Config-Driven Design

This is a pattern called "config-driven architecture" — instead of scattering your app's settings across dozens of files, you put the important decisions in one place. Want to add a module? Edit this one file. Want to reorder the curriculum? Move items around in the list. The JSON file is the single source of truth, and everything else reads from it.

Step 2: The Teaching Script

This is the heart of each lesson. Every teaching script uses four types of blocks — like stage directions for Claude.

Say: Content to deliver word-for-word — the actual teaching material
Check: STOP and wait for the student to respond — never skip ahead
Action: Commands for Claude to run — read files, create notes, search the vault
Present it like this: Formatting guidance — how to display tables, lists, or complex information

Why Three Agents?

Imagine you're managing a library. You wouldn't hire one person to do everything — you'd want a cataloger who keeps things organized, a critic who reviews new acquisitions, and a researcher who finds connections between books. That's exactly what Claude Brain does. It creates three specialized versions of Claude, each with a distinct personality and skill set.

The Three Personalities

📚

The Librarian

"Methodical, slightly fussy, always kind." Scans the vault for organizational issues and produces structured health reports. Think of a librarian who notices a mishelved book and can't rest until it's fixed.

🔍

The Critic

"Rigorous but constructive." Reviews drafts and arguments — finds gaps, unsupported claims, and weak reasoning. Like a brilliant editor who makes you groan, then three days later you realize every note was right.

🕸️

The Connector

"Enthusiastic, associative, thinks in webs." Finds hidden relationships between ideas across the vault. Like that friend who reads about architecture and immediately links it to something you wrote last week.

💡
The Power of Persona Prompting

Each agent is the same AI (Claude) given a different personality and job description. This is called "persona prompting" — and it's surprisingly effective. By telling Claude "you are a slightly fussy librarian," you get fundamentally different behavior than "you are an enthusiastic connector." Same brain, different lens. This is one of the most practical AI patterns you can use in your own projects.

The Living Vault

How a folder of plain text files becomes a knowledge system

Not a Filing Cabinet

Most people think of notes like a filing cabinet — put something in a folder, hope you remember which folder later. The Claude Brain vault works differently. Think of it like a garden: every note is a plant, and the links between notes are the roots connecting them underground. Over time, ideas cross-pollinate.

The Vault Structure

vault/ The student's Obsidian vault — open this folder in Obsidian
00-Inbox/ Raw captures, quick thoughts — the "dump it here" folder
01-Daily-Notes/ Daily journals in YYYY-MM-DD format
02-Projects/ Client work: Horizon, Bloom, ClearPath, The Synthesis
03-Research/ Deep research notes — processed and organized
04-Drafts/ Works in progress
05-References/ Style guides, checklists, rate cards
06-Templates/ Reusable note formats (daily, research, draft, etc.)
07-MOCs/ Maps of Content — index notes that connect themes
CLAUDE.md Claude's permanent memory — created during Module 1.5

The Inbox Pattern

One of the cleverest workflows in the course: dump raw thoughts into the Inbox, then let Claude sort them.

process-inbox.md 
1. List all notes in `vault/00-Inbox/`
2. If empty, congratulate the user.
3. For each note:
   a. Read its contents
   b. Categorize: Quick Thought,
      Meeting Notes, Research Lead,
      Project Task, or Reference
   c. Suggest destination folder
   d. Note connections to other notes
4. Present a triage summary
5. Ask which to process now
PLAIN ENGLISH

First, look at everything in the Inbox folder

If it's already clean — celebrate! (nice touch)

For every note sitting in the Inbox...

Actually read what's inside (not just the title)

Figure out what kind of note it is —

is it a quick thought? meeting notes?

a research lead? a task? a reference?

Recommend which folder it should live in

And find connections to existing notes

Show the student a summary of everything found

Let the student decide what to do — never act alone

Beyond Teaching: Utility Commands

The course doesn't just teach — it also builds real tools that the student keeps using after graduation. Think of it like a cooking class that sends you home with a fully stocked kitchen and a set of recipes.

📅

/daily

Creates today's daily note with a ready-made template — sections for what you did, ideas, and tomorrow's priorities.

📥

/process-inbox

Reads everything in the Inbox, categorizes each note, suggests where it should go, and finds connections to existing notes.

📊

/weekly-review

Reads all daily notes from the week, synthesizes what got done, what didn't, and identifies themes worth developing.

📝

/project-brief

Creates a structured project brief with objectives, timeline, audience, and deliverables — ready for client work.

Inside the /daily Command

daily.md 
1. Get today's date (YYYY-MM-DD)
2. Check if daily note already exists
   at `vault/01-Daily-Notes/[date].md`
   - If it exists, show it instead
3. Create the note with this format:
   ---
   date: [today]
   tags: [daily-note]
   ---
   # [today's date]
   ## What I Did Today
   ## Ideas and Observations
   ## Tomorrow's Priorities
4. Mention any piled-up Inbox notes
PLAIN ENGLISH

Figure out what today's date is

Check if you've already made a note for today

(Look in the Daily Notes folder for a file named after today)

If it's already there, just show it — don't create a duplicate

Otherwise, create a new note with this structure:

Start with metadata (the "info block")

Record today's date

Tag it as a daily note (so you can find all daily notes later)

 

Title: today's date

Section 1: What you accomplished today

Section 2: Interesting thoughts

Section 3: What to focus on tomorrow

Bonus: if the Inbox is getting full, give a gentle nudge

Hooks: Automatic Reactions

The course's most advanced feature: hooks. Think of them like email rules: "When a new note is created, automatically add the metadata block at the top."

1
Event: "A file was just created"

The hook watches for Claude writing a new file (the PostToolUse event on the Write tool)

2
Matcher: "...and it's a .md file in the vault"

Only trigger for Markdown files inside the vault folder — ignore everything else

3
Command: "Check for frontmatter, add if missing"

Automatically add the date, tags, and type metadata that every good note needs

The Design Philosophy

Six principles make this system work. These aren't just good ideas for this project — they're patterns you can use in anything you build with AI.

📋

Config-Driven

One JSON file defines the entire curriculum. Change the config, change the course. No hunting through dozens of files.

🎭

Real, Not Fake

Every demo uses the student's actual vault files. No fabricated examples. Claude reads and creates real notes.

📖

Story-First

Alex Rivera isn't a generic placeholder — a fully realized character with goals, problems, and clients that make every exercise grounded.

🎯

Structured Teaching

Say/Check/Action blocks ensure consistency across 25 modules. Check points force interactivity — no passive watching.

📈

Escalating Complexity

Level 0: install stuff. Level 2: build structure. Level 4: full automation. Each level assumes knowledge from the last.

❤️

Emotional Arc

Module 1.4's synthesis is designed to make students go "oh wow." Module 4.7 is a graduation celebration. Learning should feel like something.

The Meta-Lesson

Claude Brain teaches people to build a second brain. But the real lesson is bigger: AI is most powerful when it's given clear roles, structured instructions, and real data to work with. A well-designed prompt (like the teaching scripts) consistently outperforms a vague one. A persona-driven agent (like The Critic) gives better feedback than a generic "review this." Structure isn't a constraint — it's what makes the magic possible.
